# کنترل پروژه

## تعریف کنترل پروژه در این کار

کنترل پروژه یعنی اطمینان از اینکه:

1. محصول نهایی دقیقاً همان چیزی است که ذی‌نفع اصلی (رئیس کل) نیاز دارد.
2. هیچ ابهامی در شاخص‌ها، واحدها و معانی باقی نماند.
3. تغییرات و بازخوردها به‌صورت کنترل‌شده اعمال شوند.
4. قوانین حاکم (هارنس) نقض نشوند.

## ارکان کنترل

| رکن | توضیح | محل مستندسازی |
|-----|-------|----------------|
| دامنه | چه چیزی داخل و خارج پروژه است | `02-scope-and-objectives.md` |
| قوانین حاکم | قواعد غیرقابل مذاکره | پوشه `harness/` |
| تصمیمات | ثبت چرایی انتخاب‌ها | پوشه `decisions/` |
| بازخورد | اعمال نظرات کاربر به‌صورت نسخه‌دار | تاریخچه نسخه‌های HTML |
| کیفیت | معیارهای پذیرش داشبورد | `harness/02-clarity-rules.md` |

## چرخه کنترل

```
درخواست / بازخورد کاربر
        ↓
بررسی تطابق با هارنس
        ↓
ثبت تصمیم (در صورت نیاز ADR)
        ↓
اعمال تغییر در طراحی
        ↓
بازبینی شفافیت و واحدها
        ↓
نسخه جدید قابل مشاهده
```

## معیارهای پذیرش کلی

یک داشبورد یا پنل تنها زمانی پذیرفته می‌شود که:

- عنوان آن بدون نیاز به توضیح اضافی قابل فهم باشد.
- واحد اندازه‌گیری مشخص باشد.
- منبع داده (جداول Dimension/Fact یا Agg*) مشخص باشد.
- توضیح کوتاه و شفاف در باکس راهنمای پایین صفحه وجود داشته باشد.
- از دید رئیس کل معنادار باشد (نه دید عملیاتی روزانه یک شرکت).
