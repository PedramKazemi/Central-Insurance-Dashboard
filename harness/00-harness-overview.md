# هارنس پروژه (Project Harness)

## هارنس چیست؟

هارنس مجموعه‌ای از **قوانین غیرقابل نقض** است که تمام طراحی‌ها، تصمیمات و خروجی‌های این پروژه باید از آن پیروی کنند.

هر تغییری که با هارنس در تضاد باشد، باید یا هارنس را آگاهانه به‌روزرسانی کند یا رد شود.

## اجزای هارنس

| فایل | موضوع |
|------|--------|
| `01-design-principles.md` | اصول کلی طراحی داشبورد |
| `02-clarity-rules.md` | قوانین شفافیت و حذف ابهام |
| `03-visual-rules.md` | قوانین بصری و ظاهری |
| `04-grafana-constraints.md` | محدودیت‌ها و قابلیت‌های Grafana 13 |
| `05-demo-mode-rules.md` | قوانین حالت نمایشی (دمو) |

## اصل طلایی

> **هیچ چیزی نباید گنگ باشد.**  
> اگر کاربر مجبور شود بپرسد «این یعنی چه؟» یا «واحدش چیست؟»، قانون شفافیت نقض شده است.

## نحوه اعمال

- قبل از هر خروجی جدید، چک‌لیست هارنس بررسی شود.
- در صورت تعارض بین زیبایی و شفافیت، **شفافیت اولویت دارد**.
- در صورت تعارض بین جزئیات فنی و دید رئیس کل، **دید رئیس کل اولویت دارد**.
